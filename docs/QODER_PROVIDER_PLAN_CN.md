## 预期使用流程

管理员进入「账号管理 → 添加账号」，选择 Qoder 和 OAuth，打开官方授权页面并选择账号。页面自动等待授权结果，随后保存账号，允许分组、调度、测试、同步模型及重新授权。

每个账号独立保存凭证，新增账号不能覆盖已有账号的登录状态。

## 实现范围

### 支持商登记

在 `backend/internal/domain/constants.go` 和 `backend/internal/domain/platforms.go` 中登记 `qoder`，使用 OpenAI 网关协议族。

同步前端的 `frontend/src/constants/platformCatalog.builtin.json` 与必要的类型、图标和显示配置。检查分组及 API 密钥的支持商列表，保证 Qoder 可以正常选择。

### 网页设备授权

参照现有支持商，在管理员接口下增加 Qoder 的授权开始、轮询、取消、刷新与重新授权入口。

国内版已知授权流程：

1. 后端生成秘密 `verifier`、公开 `challenge` 和 `nonce`。
2. 浏览器打开 `https://qoder.com.cn/device/selectAccounts`。
3. 后端调用 `https://openapi.qoder.com.cn/api/v1/deviceToken/poll`。
4. 返回凭证并查询用户信息，保存到对应账号的凭证字段。

临时授权状态应有有效期、管理员归属和一次性消费校验。不能把秘密 `verifier` 暴露在浏览器 URL 或日志中。

授权接口与续期接口的令牌字段需要分别解析，以实际响应为依据。凭证更新必须是事务操作，避免续期和重新授权相互覆盖。

### 请求转发

在 OpenAI 兼容网关中增加 Qoder 的实际转发路径，复用已有的调度、并发、分组、记录与协议转换机制。

每次请求使用所选账号的凭证生成 COSY 认证头，并编码实际正文。解析返回流外层信封的业务状态，再转成标准聊天补全响应。

模型目录应实时获取并缓存，建立显示名与原生标识映射。工具调用需要保留历史消息、工具结果及分段参数，并验证强制工具选择和禁止并行的语义。

### 与现有部署衔接

服务器先保留正在使用的可执行程序。新版本在独立目录构建、测试，确认后再由主会话安排运行服务的切换。

现有运行程序的源码关联文件只用于追溯，不应直接改成运行文件的符号链接，避免未提交的源码编辑影响线上进程。

## 验收条件

- 网页能添加 Qoder OAuth 账号，并自动完成授权等待。
- 两个账号分别授权后，凭证相互独立。
- 模型同步、普通聊天、流式聊天及工具调用完整往返通过。
- 凭证真实续期与重新授权通过。
- 授权取消、过期、失败与重复提交有明确状态。
- 前端类型及多语言键检查、相关后端测试通过。
- 发布前检查补丁不包含令牌、密码、密钥或运行数据。

实现与接口说明见 `docs/QODER_NATIVE_CN.md`。模拟双账号隔离、取消、过期、重复保存、协议和凭证条件更新测试已通过；服务器已验证网页授权、重新授权、真实续期、14 个模型目录，以及聊天补全、Responses、Messages 的文本和函数工具完整往返。现有密钥已切换至原生分组，旧 Python 服务停用，回滚资料保留。
