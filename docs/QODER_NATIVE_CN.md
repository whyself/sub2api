# Qoder 原生支持商

## 使用流程

1. 在「账号管理 → 添加账号」选择 **Qoder**。
2. 设置名称、分组、并发等账号配置，进入授权步骤。
3. 点击「打开官方授权页」，在 Qoder 国内版选择账号并确认。
4. 网页自动轮询，授权成功后由后端保存对应账号并同步可用模型。
5. 为 Qoder 分组创建或绑定 API 密钥，即可使用统一网关。

已有 Qoder 账号的「重新授权」使用相同的网页流程。单账号和批量刷新使用统一的令牌刷新服务。

## 原生实现

- 平台标识：`qoder`，账号类型：`oauth`。
- 网关族：OpenAI 兼容网关，原生上游协议为聊天补全。
- `/v1/responses` 与 `/v1/messages` 复用已有转换与工具历史处理流水线。
- `backend/internal/pkg/qoder` 负责 PKCE、业务接口、COSY 认证、正文编码和流式解包。
- `QoderService` 负责管理员归属、临时授权会话、账号保存、重新授权和目录缓存。
- 后台续期、请求时续期和管理员刷新共享统一刷新 API；完整旧凭证与代理匹配后才能原子保存。
- 重新授权保留同一账号的实例身份，并恢复凭证错误造成的阻塞；人工停用状态保留。

原有 Python 程序仍在 `tools/qoder-bridge` 中作为可回溯的源码快照。原生 Qoder 平台转发由 Go 后端直接完成。

## 授权接口

管理员接口位于 `/api/v1/admin/qoder/oauth`：

| 路径 | 方法 | 作用 |
| --- | --- | --- |
| `/start` | POST | 生成设备授权会话与公开 URL |
| `/poll` | POST | 查询授权状态；返回不敏感摘要 |
| `/commit` | POST | 由后端消费会话并保存新账号或重新授权 |
| `/cancel` | POST | 取消所属的授权会话 |

临时会话有效期十分钟，校验管理员归属与重新授权目标。重复提交返回同一个保存结果。访问令牌、续期令牌和秘密 `verifier` 均不返回网页。

状态包括等待、就绪、完成、取消和过期。请求失败显示错误并允许重试；保存响应丢失时，继续轮询原会话可取回已经完成的结果。

## 模型与工具

目录缓存按账号与访问令牌版本区分，避免不同账号共享可用模型范围。显示名与原生标识分别保存和解析；新增或下线模型由实时目录决定。

标准函数工具、工具结果历史、分段参数及推理字段得到保留。上游未原生执行的指定工具和禁止并行要求，在转换层补充约束并验证。带严格约束的请求会先收齐结果，再向调用方回传。

当前范围为国内版、单项生成与标准函数工具；原生实时、生图、嵌入和压缩能力不会被自动宣称为可用。结构化输出、种子等未验证的关键参数明确报错。

## 源码与运行关联

服务器使用构建后的独立二进制。部署记录保存仓库、分支、提交和二进制校验值；工作目录中的未提交编辑不会直接改变运行文件。

可通过 `SUB2API_UPDATE_REPOSITORY=whyself/sub2api` 将网页更新检查绑定到 fork 的发布仓库。没有发布包时，通过已验证的 Git 提交构建和部署。

## 验证

- 协议客户端：PKCE、秘密字段隔离、COSY 摘要、真实续期字段、流内错误、截断流与工具分段合并。
- 授权服务：两个模拟账号独立授权、管理员归属、取消、过期和并发重复提交。
- 持久化：凭证及代理条件更新、原子调度失效事件、重新授权状态恢复。
- 前端：授权等待、自动保存、关闭取消、平台目录及语言键完整性。
- 真实服务器：原生客户端已查询 14 个模型并正常完成流式聊天。

网页授权、重新授权以及公共网关的完整调用验收将在服务器版本切换后记录。
